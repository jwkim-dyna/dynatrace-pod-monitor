# Pod 상태 모니터링

현재 실행 중인 Dynatrace 환경의 실제 Smartscape 데이터로 클러스터·네임스페이스별 Pod 상태를 표시하는 읽기 전용 커스텀 앱입니다. 앱에 더미 데이터, 데모 데이터, 실패 시 샘플로 대체하는 경로가 없습니다.

## 실행

새로 복제한 저장소에서는 `Copy-Item app.config.example.json app.config.json`을 실행하고,
`app.config.json`의 `environmentUrl`을 사용할 Dynatrace 환경 주소로 바꿉니다. 실제 환경 설정은 Git에 저장하지 않습니다.

```powershell
npm ci --ignore-scripts
npm run start -- --no-open --port 3003
```

App Toolkit이 출력하는 인증 주소를 열어 기존 Dynatrace 계정으로 로그인합니다. 실행 후 `http://localhost:3003/ui`를 열면 실제 환경 데이터를 조회합니다. 인증 정보는 App Toolkit이 관리하며 소스에 토큰을 넣지 않습니다. Dynatrace 안에서 볼 때는 개발 서버가 출력하는 환경용 URL을 사용합니다.

개발 환경은 `app.config.json`의 `environmentUrl`로 지정합니다. 배포된 앱은 실행 중인 고객사 환경을 SDK로 확인하며, 개발 환경의 주소·클러스터 UID·네임스페이스를 데이터 조회에 고정하지 않습니다. 앱 ID와 버전은 `app.config.example.json`에서 확인할 수 있습니다. 현재 로그인한 사용자의 조회 권한과 고객사 환경의 Kubernetes Smartscape·Grail 수집이 필요합니다.

## 기능

- 기본 Kubernetes·QuickStart 앱을 참고해 DynatraceFlow 글꼴과 Strato의 배경·테두리·텍스트·선택 색상 토큰을 사용한다. 검색·선택·체크박스·버튼·아이콘·표·차트는 공식 컴포넌트를 적용하며 상단 앱 탐색, 조회 도구, 요약 카드, 문제 목록, 팝업·상세 패널을 같은 시각 체계로 구성한다.
- 모든 클러스터 또는 개별 클러스터를 선택하고, 선택한 범위의 모든 Namespace를 조회한다. 특정 클러스터·Namespace 이름이나 접두어로 제한하지 않는다. 전체 클러스터 보기에서도 같은 이름의 Namespace·Workload는 클러스터 UID별로 구분한다.
- 클러스터 목록 자동 조회, 전체·개별 클러스터 선택. 저장된 클러스터를 찾지 못하면 선택을 요청하며 전체 조회로 임의 확대하지 않는다.
- Namespace 전체·단일·다중 선택과 검색. 클러스터 선택과 각 클러스터의 Namespace 선택을 브라우저에 환경별로 자동 저장하여 앱을 닫았다 다시 열어도 복원한다. 전체 클러스터 범위의 선택도 별도로 보관한다. 전체 선택과 빈 선택도 구분해 저장하며, 저장을 차단한 브라우저에서는 저장 불가를 표시한다. 다른 브라우저·기기 간 동기화는 포함하지 않는다.
- Namespace별 이름·상태 집계·타일 구분. 세로 막대 하나가 Pod 하나이며 공백 없이 붙여 표시하고 전체 바를 하나의 선택 영역으로 사용
- 문제 상태의 빨간 Pod 막대·팝업 타일은 1.6초 주기로 밝은 빨간 빛을 내며 반짝인다. 문제 Pod가 있는 Workload 바는 빨간 외곽선·후광과 문제 개수 배지로 강조하고, Namespace에는 큰 문제 개수 배지를 표시한다. 정상 막대는 채도를 낮춘 녹색으로 표시한다. 크기·위치를 변경하지 않으며 모션 축소 설정에서는 정적으로 표시한다.
- 정상은 차분한 녹색 체크, 경고는 밝은 노란 배경·진한 느낌표·작은 모서리, 문제는 선명한 빨간 배경·흰색 ×·반짝임으로 구분한다. 보드 위에 실제 타일과 같은 색의 범례를 제공하며 완료·확인 불가는 회색을 유지한다.
- 호버 설명은 32px 고정 한 줄로 표시하며 타일의 호버 위치·기울기는 바뀌지 않아 Namespace 배치를 유지
- Dynatrace 사용자 light/dark/auto 테마를 따라 배경·글자·표·차트 색상을 적용. 로컬 단독 페이지는 브라우저 테마를 따름. SDK 테마 변경을 확인해 새로고침 없이 반영하며 선택 범위·상세를 유지
- 테마는 항상 환경 연동만 사용한다. 앱 내 수동 테마 선택과 저장된 라이트·다크 재정의는 적용하지 않는다.
- 상태 집계·검색은 타일을 숨기지 않고 일치 항목을 강조. Namespace·이름 정렬을 유지해 상태 변경 때 재배치하지 않음
- 우측에 문제·경고·확인 불가 Pod를 원인과 함께 우선 표시
- 녹색 정상, 노란색 경고, 빨간색 문제; 완료/상태 미확인은 회색
- 상태 요약 및 정렬·페이지 처리가 가능한 Table
- Pod 선택 시 클러스터·Namespace·Pod UID로 최신 수집 상태를 별도 조회하고 Ready, Node, 누적 재시작, Pod 조건, 최근 Kubernetes 이벤트 표시. 컨테이너별 실행 상태 목록은 생략하며 같은 Pod를 다시 클릭해도 새로 조회
- 상세 상태 확인 후 최근 30분 CPU·메모리를 자동 조회 (1분 간격, 일반 컨테이너 합계). 메트릭은 선택 시 및 수동 갱신 때만 조회. 추가 탐색은 기존 Dynatrace Kubernetes 앱으로 이동
- 상세에 일반·init 컨테이너의 CPU/MEM requests·limits 표 제공. 원본 Pod 설정을 우선하고 누락된 값은 같은 컨테이너의 최근 15분 수집 메트릭으로 보완. 출처와 관측 시각을 표시하고 다른 UID·생성 이전·오래된 값을 사용하지 않음. `—`는 미설정 또는 미수집이며 임의의 0으로 채우지 않음
- 최초 진입·조회 범위 변경 시 즉시 조회, 전체 및 선택 Pod 상태는 이후 60초 자동 갱신, 수동 갱신 및 마지막 성공 시각
- 조회 실패 시 이전 결과와 오류를 표시하고, 범위 변경 후에는 이전 범위 데이터를 표시하지 않음

## 고객사 환경 배포

Kubernetes 클러스터·Namespace·Pod·Workload가 Smartscape에 수집되고, 선택 Pod의 메트릭·이벤트가 Grail에 수집되는 고객사 환경에서 사용한다. `app.config.json`의 Smartscape·metrics·buckets·events 읽기 범위와 실제 사용자의 조회 권한이 필요하다.

고객사 환경에 업로드할 ZIP만 생성하려면 다음 명령을 사용한다. 이 명령은 원격 앱을 설치하거나 업데이트하지 않는다.

```powershell
npm run package
```

생성 위치는 `out/artifact.zip`이다. 이 패키징 명령은 로컬에서 빌드·압축하며 원격 게시·설치·매니페스트 서버 검증을 수행하지 않는다. 고객사에서 제공하는 앱 업로드 절차로 ZIP을 설치할 때 대상 환경에서 검증한다. 고객사 주소를 지정해 App Toolkit으로 직접 배포할 때는 다음 명령을 사용한다. 해당 고객사 배포 권한으로 직접 인증해야 한다.

```powershell
npm run deploy -- --environment-url https://CUSTOMER.apps.dynatrace.com --no-open
```

설치 후 앱 안에서 대상 클러스터와 Namespace를 선택한다. 데이터 조회 환경과 기본 Kubernetes 앱 링크는 런타임 SDK의 환경 주소를 사용한다. 로컬 개발 주소와 고객사 배포 주소는 서로 다른 브라우저 저장소이므로 Namespace 설정은 각 위치에서 저장한다.

## 상태와 데이터 해석

현재 결과는 **최근 15분 이내 Smartscape에서 관측된 Pod의 최신 수집 상태**입니다. 조회의 시간 범위와 별개로 lifetime 종료 시각을 명시적으로 필터링해 오래된 Pod가 집계에 섞이지 않게 합니다. 마지막 관측 시각 자체가 없는 Pod는 확인 불가로 표시합니다. Kubernetes API를 실시간으로 직접 조회하는 앱은 아닙니다. 삭제된 Pod가 수집 지연에 따라 잠시 남거나 수집이 중단된 클러스터의 Pod가 범위에서 빠질 수 있습니다. Pod 상세에서 마지막 관측 시각을 확인할 수 있습니다. 클러스터 목록은 최근 1시간의 관측 데이터이며, 최근 15분 내 관측이 없는 클러스터는 상태 변경 또는 수집 지연 가능성을 안내합니다. Pod는 최근 15분 관측 기준으로 조회하며 Namespace 목록은 최근 1시간 범위입니다. 화면 새로고침 간격 1분과 관측 범위 15분은 서로 다른 설정입니다.

Running이면서 Ready=True이면 정상입니다. 현재 Failed, 실행 오류, CrashLoopBackOff, 이미지 오류 또는 현재 비정상 컨테이너 종료는 문제로 표시합니다. Pending과 Running+NotReady는 경고으로 표시하며 5분 지속 여부를 확인할 수 있으면 설명에 붙입니다. Succeeded는 정상 완료입니다. 필수 상태 또는 관측 시각이 없으면 확인 불가로 표시합니다. 과거 OOM과 누적 재시작만으로 현재 색상을 바꾸지 않습니다.

재시작 숫자는 Pod 객체의 컨테이너 누적 restartCount 합계이며, 최근 5분 발생 건수가 아닙니다. 최근 이벤트는 1시간, 최대 20건으로 제한합니다. UID가 있는 이벤트는 해당 Pod UID와 일치할 때 표시하며, UID가 없는 이벤트는 같은 이름의 이전 Pod 이력일 수 있음을 화면에 알립니다.

CPU·메모리 사용률은 일반 컨테이너의 실제 사용량 합계를 동일 시간의 Limit 합계로 나눈 백분율입니다. CPU 설정값과 절대 사용량은 core로 통일합니다(100m → 0.1 core, 2 → 2 core). Grail 메타데이터의 Core/Millicore/Microcore/Nanocore 변환을 적용하며 사용률은 %를 유지합니다. Limit이 없거나 일부 컨테이너의 Limit 메트릭이 누락된 구간은 0%로 대체하지 않습니다. 비율을 계산할 수 없는 Pod는 실제 사용량을 표시하고 이유를 안내합니다. 사용량 자체를 계산할 수 없는 CPU·MEM 항목은 빈 카드·평균·최대 표시를 생략하고, "컨테이너 메트릭 일부가 없어서 Pod 전체 사용량을 계산할 수 없습니다."라는 문구만 한 번 표시합니다. Init 컨테이너는 리소스 합계에서 제외합니다. Pod UID를 우선 검증하고, UID가 없는 메트릭도 Pod 생성 이전 구간을 표시하지 않습니다. 차트 시간은 Dynatrace 사용자 시간 설정을 따르며, 마지막 관측·값의 별도 표시는 KST입니다.

Namespace 안에 작은 Workload 이름표와 얇은 선으로 구분합니다. Workload 수치는 **실행/계획**입니다. 실행은 최근 관측된 Running Pod 수(종료 중 제외)이며 Ready 수와 다릅니다. 계획은 Deployment·StatefulSet의 `spec.replicas`, DaemonSet의 `status.desiredNumberScheduled`를 실제 Smartscape 객체에서 조회합니다. Pod 목록 개수로 계획 수를 추정하지 않으며, CronJob·Job 등 상시 replica 목표가 없거나 수집되지 않은 경우 `—`입니다. 0으로 축소된 설정은 `0/0`을 유지하고 목표보다 적으면 노란색으로 강조합니다. 관측된 Pod가 없는 Workload도 표시하며 가짜 타일을 추가하지 않습니다. Workload 목표 수는 같은 클러스터·Namespace 범위에서 1분마다 갱신하고, 오래되거나 조회 오류·부분 결과가 있으면 `—`와 안내를 표시합니다. 이름표에 마우스를 올리면 Ready·전체 관측 Pod 수·목표 출처·관측 시각을 확인할 수 있습니다.

모든 타일을 펼쳐 두며 `Workload별 구분` 옵션을 끄면 Namespace 단위로만 표시합니다. 선택은 테마 변경·새로고침 후에도 유지됩니다. 전체 바를 누르면 화면 중앙에 해당 Workload의 큰 Pod 타일 목록만 담은 팝업이 열립니다. Workload별 구분을 끄면 해당 Namespace의 Pod 목록을 표시합니다. 팝업 안에서 Pod를 누를 때 오른쪽 상세 패널이 슬라이드로 열리며, UID로 최신 상태를 확인한 후 해당 Pod의 메트릭을 조회합니다. 상세 패널을 닫으면 Pod 목록으로 돌아옵니다. 각 창은 바깥 클릭·Esc·닫기 버튼으로 닫히고 키보드 포커스는 맨 위 창 안에 유지됩니다. 모션 축소 설정에서는 애니메이션을 생략합니다. 로그 연결은 후속 확장 범위입니다. 앱은 Kubernetes 리소스 또는 모니터링 설정을 변경하지 않습니다.

Pod 결과가 10,000개를 초과하거나 Grail이 제한 경고를 반환하면 부분 결과임을 표시합니다. 보드에는 반환된 모든 Pod를 표시하며 Namespace별 타일 제한은 없습니다. 집계는 테이블 첫 페이지가 아닌 반환된 전체 Pod 기준입니다. 일반 데스크톱 화면에서 클러스터 하나의 약 250개가 들어가는 밀도로 설계했으며 작은 화면·더 큰 규모에서는 스크롤이 필요합니다. 더 큰 규모에서는 분할 조회와 서버 집계가 필요합니다.

## 검증

```powershell
npm run build
npm run lint
npm test
```

테스트의 상태 입력은 판정 회귀 검증에만 사용되며 앱 실행에 포함되지 않습니다. 실제 환경의 조회·필터·상세 화면은 브라우저에서 별도로 확인합니다.

현재 개발 환경의 실제 전체 Namespace 조회와 선택 범위 전환을 브라우저에서 검증합니다. 다중 클러스터의 동일 Namespace·Workload 구분과 환경·클러스터별 저장은 회귀 테스트로도 확인합니다. 상태 강조 시 모든 조회 Pod를 유지하며, 화면 크기와 Pod 분포에 따라 스크롤이 필요할 수 있습니다.
